# 이미지 저장

글쓰기의 파일 삽입은 로그인 후 `POST /api/images`에 multipart 파일을 전송합니다.
서버에서 실제 파일 형식을 검증하고, 긴 변 최대 1600px의 WebP로 변환합니다.
JPG·PNG·WebP 정지 이미지, 파일 최대 10MB, 디코딩 최대 4천만 픽셀을 지원합니다.

- 이미지 파일: 기본 `project/storage/uploads/<UUID>.webp`
- 소유자 정보: 같은 폴더의 `<UUID>.webp.json`
- 글 본문 및 서버 임시저장: 이미지 데이터 대신 `/api/images/<UUID>.webp` URL
- 외부 이미지 주소 삽입: 원본 URL을 저장하며 외부 파일을 복제하지 않습니다.

`UPLOAD_DIR` 환경변수로 저장 폴더의 절대 경로를 지정할 수 있습니다.
예: `UPLOAD_DIR=D:/DeveloperBlogData/uploads` 또는 `UPLOAD_DIR=/data/uploads`.
환경변수가 없으면 앱 실행 디렉터리의 `storage/uploads`를 사용합니다.

배포 시 이 폴더를 **영구 볼륨에 연결**하고 DB와 함께 백업해야 합니다.
소유자 JSON 파일도 함께 보관해야 이미지 접근 권한이 유지됩니다.
여러 앱 인스턴스에서는 같은 저장 볼륨을 공유해야 합니다.
임시 파일시스템을 사용하는 서버리스 배포에서는 이 구현 대신 S3/R2 같은
오브젝트 스토리지와 비공개 파일 접근 처리를 연결해야 합니다.
현재 외부 스토리지 연동은 구성되어 있지 않습니다.

이미지 조회는 소유자 또는 이미지를 포함한 글의 열람 권한을 확인합니다.
아직 발행하지 않은 이미지와 나만 보기 글의 이미지는 소유자만 볼 수 있습니다.
글 공개 범위를 변경한 후에도 이전 응답이 공유되지 않도록 이미지는 캐시하지 않습니다.
글 발행 시 다른 사용자의 로컬 업로드 URL을 재사용할 수 없습니다.

기존 Base64 글은 읽기 호환성을 유지하지만 신규 발행에는 허용하지 않습니다.
기존 DB 이미지의 일괄 변환은 실행하지 않았습니다.
서버 임시저장은 `PostDraft`에 저장됩니다. 새 글용 임시 글과 각 게시글의 수정용 임시 글을
별도로 보관하며, 버전 검사로 다른 창의 저장 내용을 덮어쓰지 않습니다.
글쓰기의 `임시 글 삭제`로 명시적으로 버릴 수 있고, 보관 중인 임시 글은 자동 만료되지 않습니다.
기존 브라우저 임시 글은 서버 임시 글이 없을 때 불러올 수 있으며 이어서 작성하면 서버에 저장됩니다.

`ImageAsset`, `PostImage`, `DraftImage`가 이미지 사용 여부를 추적합니다.
글·임시 글에서 제거된 이미지는 마지막 연결이 사라진 시점부터 24시간 유예합니다.
다른 글 또는 임시 글에서 사용 중이거나, 실행 취소 후 다시 저장한 이미지는 삭제하지 않습니다.
글 삭제와 카테고리 삭제도 같은 정리 규칙을 적용합니다.
서버가 실행 중이면 시작 1분 뒤와 이후 매시간 정리합니다. 작업당 최대 100개를 삭제합니다.
여러 서버의 저장·삭제·정리는 PostgreSQL 트랜잭션 잠금으로 조정합니다.

외부 스케줄러가 필요한 경우 `CRON_SECRET`을 설정하고
`POST /api/maintenance/images`를 `Authorization: Bearer <CRON_SECRET>` 헤더와 함께 호출합니다.
비밀 값이 설정되지 않았거나 인증에 실패하면 실행되지 않습니다.
기존 파일은 최초 정리 시 DB에 등록되며, 기존 글 연결을 확인한 다음 유예 기간을 시작합니다.

DB 연결은 UTC 세션을 사용합니다. 화면에서는 한국어 날짜 형식으로 표시합니다.

배포 전 `npx prisma migrate deploy --config prisma7.config.ts`로 마이그레이션을 적용하세요.

검증: `node --experimental-strip-types --test tests/image-storage.test.mjs`

전체 통합 검증: `npm run build` 후 `node --test tests/post-lifecycle.test.mjs`.
통합 테스트는 별도의 임시 DB와 업로드 폴더를 생성하고 종료 시 제거합니다.
설정된 PostgreSQL 계정에 테스트 DB 생성 권한이 필요합니다.
